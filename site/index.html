Leanwork SDD · v1.9.0

Do briefing ao review, sem perder o fio.

Um pipeline Spec-Driven Development em seis skills coordenadas: arquitetura, requisitos, interface, plano, execução e review. Cada artefato declara seus elos por ID, e o /leanwork-trace percorre a cadeia inteira apontando onde ela se rompe.

O pipeline

Seis fases,
uma cadeia só.

A execução é uma fase do pipeline, não um intervalo entre fases. As fases 5 e 6 se alternam tarefa a tarefa até o plano fechar — e o plano é o único lugar onde o estado de execução vive.

O loop de execução

O plano é a
fonte de verdade.

Um estado que o plano não declara não existe para o pipeline. O vocabulário de status é fixo e funciona como contrato entre o plano e os comandos que o leem.

Pendente

Tarefa aguardando. Elegível quando todas as dependências estiverem concluídas.

Em andamento

Marcado antes da primeira linha de código. É o que torna a sessão recuperável.

Concluído

Critérios de aceite marcados, typecheck limpo e suíte verde. Nunca com teste vermelho.

Bloqueado

Motivo no histórico. É também para onde um finding bloqueante do review devolve a tarefa.

/leanwork-execute T-04

  1. Carrega o PRD, a arquitetura e a SPEC-UI nos IDs que a tarefa declara
  2. Para e reporta se algum ID referenciado não existir
  3. Escreve o teste na costura antes do código de produção
  4. Roda typecheck e build antes da suíte
  5. Fecha o estado no plano e sugere o review

/leanwork-review T-04

  1. Detecta a stack do projeto por cascata, sem presumir tecnologia
  2. Avalia os seis eixos com evidência de arquivo e linha
  3. Emite R-01..R-XX por severidade
  4. Finding bloqueante devolve a tarefa para Status: Bloqueado
  5. Re-review de round N+1 entra no fluxo principal

Quem implementou não decide se a implementação passou: o /leanwork-execute sugere o review, mas nunca o roda por conta própria.

Código

Projeto sem interface pula a fase 3 inteira, e as colunas de UI somem da matriz — ausência não vira gap. Lacuna declarada vale mais que lacuna preenchida: nenhuma skill inventa para fechar a matriz.

O review

Seis eixos,
com evidência.

Os eixos 1 a 5 aplicam sempre. O eixo 6 só entra quando o projeto tem SPEC-UI e a tarefa é de interface. Cada finding cita arquivo e linha — sem achismos.

01

Aderência ao plano

A tarefa T-XX foi entregue como prometida? Escopo expandido em silêncio é finding.

02

Rastreabilidade

Commits, testes e código preservam os IDs que amarram o trabalho ao requisito?

03

Aderência ao spec

Cada RN foi concretizada, cada CA tem teste e cada ADR foi respeitada?

04

Cobertura de teste

Os testes prometidos existem? Os casos de borda estão cobertos?

05

Qualidade do código

Princípios universais mais os padrões específicos lidos do CLAUDE.md do projeto.

06

Conformidade de interface

Estrutura, estados e comportamento — nunca estética. Estado ausente é bloqueante; detalhe visual não vira finding.

Bloqueante

Merge negado. Devolve a tarefa para Bloqueado no plano.

Importante

Resolver agora ou na próxima tarefa, com a decisão registrada.

Sugestão

Opcional. Fica na mesa sem travar a entrega.

Filosofia

O que sustenta
o pipeline.

SDD pragmático, não ortodoxo. As divergências deliberadas com a literatura estão escritas no REFERENCES.md — discordar é mais fácil quando a fonte está na mesa.

Lacuna declarada vale mais que lacuna preenchida

Nenhuma skill inventa para fechar a matriz. Matriz honestamente incompleta é informação; matriz fechada com suposição é armadilha.

Stack-agnóstico no núcleo

Nenhuma skill traz tecnologia pré-definida. Exemplos com código real ficam isolados em stacks/, nunca misturados ao núcleo.

Sem cronograma, sem estimativa

O pipeline produz o quê, o porquê e em que ordem. Quando e quanto são responsabilidade do planejamento de sprint.

Português é padrão

Todos os artefatos saem em PT-BR. Termos técnicos consagrados podem ficar em inglês.

IA-friendly por design

IDs estáveis, pontos de validação humana explícitos e critérios de aceite testáveis — otimizado para ser consumido por agente.

Progressive disclosure

SKILL.md curta conduz a conversa. Os templates grandes ficam em references/, carregados só na hora de gerar o documento.

Instalação

Marketplace
local.

O plugin é distribuído internamente: o próprio repositório é o marketplace, adicionado por caminho local. Nada aqui depende de rede além do git clone.

Uso permanente

Para atualizar depois de um git pull, rodar claude plugin marketplace update leanwork.

Desenvolvimento do plugin

A flag --plugin-dir carrega o plugin direto do diretório, sem instalar. Vale apenas pela sessão atual. 

# Uso permanente (equipe)
$ git clone https://github.com/leanwork/leanwork-sdd.git
$ claude plugin marketplace add ./leanwork-sdd
$ claude plugin install leanwork-sdd@leanwork

# Desenvolvimento do próprio plugin
$ claude --plugin-dir /caminho/para/leanwork-sdd

# Confirmar que as skills carregaram
> /plugin
